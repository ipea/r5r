# AGENTS.md — r5r

**Project:** r5r — R package for rapid realistic multimodal routing and accessibility analysis (walk, bike, transit, car) on top of Conveyal's R5 engine (https://github.com/conveyal/r5), bridged through rJava and a small in-house JAR (`java-r5rcore`)
**Maintainer:** Rafael H. M. Pereira (aut, cre) — Ipea, Institute for Applied Economic Research. Authors: Marcus Saraiva, Daniel Herszenhut, Alex Magnus, Matthew Wigginton Bhagat-Conway (see `r-package/DESCRIPTION` for the full list)
**Repo:** https://github.com/ipea/r5r · **Branch:** `master` (not `main`) · **Site:** https://ipea.github.io/r5r/ · **Version:** 2.4.0.9000 (dev) · **Language:** English

**Monorepo:** the R package lives in `r-package/`; the Java bridge in `java-r5rcore/`. There is no `DESCRIPTION` at the repo root, so every devtools / `R CMD` call takes the explicit path, and the release gate is `/r-package-check r-package`.

## Core Principles

- **Plan first** — enter plan mode before non-trivial tasks; then create an adversarial agent to review the plan, improve it and make it simple with less code intervention; once agents reach a consensus about the plan, save it to `quality_reports/plans/`
- **`r-package/R/` is authoritative** — `man/` and `NAMESPACE` are generated by roxygen2. Never hand-edit them; edit the roxygen blocks and run `devtools::document("r-package")`
- **The release gate is `R CMD check --as-cran`** — 0 errors, 0 warnings, every remaining NOTE justified in `r-package/cran-comments.md`. Run `/r-package-check r-package` before any release or merge touching `R/`, `tests/`, or `DESCRIPTION`
- **The little JAR is built by CI, never by hand** — `r-package/inst/jar/r5r.jar` is produced by the `build-jar` job in `.github/workflows/jar-and-R-ci.yaml`, which commits `Rebuild JAR for commit <sha>` to the pushed branch. Do not stage a locally built JAR. Rules: [`.claude/rules/java-r5rcore-conventions.md`](.claude/rules/java-r5rcore-conventions.md)
- **Minimal interventions** — change only what the request or the fix requires; keep text output concise
- **`[LEARN]` tags** — when corrected, or when a non-obvious approach is confirmed, append `[LEARN:category] wrong → right` to [MEMORY.md](MEMORY.md)

Cross-session context lives in [MEMORY.md](MEMORY.md); plans, specs, and session logs are in `quality_reports/` (local, gitignored). The r5r-specific Claude Code layer is committed in `.claude/`: path-scoped **rules** (`rules/`) and the review **agents** (`agents/`: `r-reviewer`, `r-package-reviewer`, `verifier`), which override user-level agents of the same name. **Skills** are not stored here — they come from each contributor's user-level `~/.claude/skills/`, which takes precedence over project skills. `CLAUDE.md` only imports this file; machine- and person-specific notes go in a gitignored `CLAUDE.local.md`.

## Commands

Run from the repo root; every call carries the package path.

```r
# Regenerate docs + NAMESPACE after editing roxygen blocks
devtools::document("r-package")

# Test suite — needs Java 21 and NOT_CRAN=true (tests/testthat.R sets -Xmx2G; setup.R builds two networks, ~2-3 min warm-up)
Sys.setenv(NOT_CRAN = "true"); devtools::test("r-package")

# Full CRAN-readiness check (slow — run in the background and monitor)
devtools::check("r-package", args = "--as-cran")

# Coverage / site
covr::package_coverage("r-package")
pkgdown::build_site("r-package")
```

```bash
# Local R CMD check equivalent to CI
R CMD build r-package && R CMD check --as-cran r5r_*.tar.gz

# Local smoke build of the little JAR (needs R + devtools on PATH: build.gradle calls download_r5() to resolve the R5 JAR)
cd java-r5rcore && ./gradlew build        # output: build/libs/java-r5rcore-*.jar — do NOT copy into inst/jar and commit
```

Users must set `options(java.parameters = "-Xmx<N>G")` **before** `library(r5r)`; `.onAttach` reminds them, `r5r_sitrep()` reports the current value.

**CRAN submission:** bump `Version` in `DESCRIPTION`, finalize `NEWS.md`, refresh `cran-comments.md`, confirm the CI matrix is green, then `devtools::release("r-package")` (maintainer-only, not automated).

## Java / R5 Bridge Contract

| Item | Where | Rule |
|---|---|---|
| Java version | `R/utils.R` → `start_r5r_java()` | Exactly 21 is enforced at JVM start (aborts otherwise). `SystemRequirements: Java JDK (>= 21.0)` |
| Big R5 JAR (downloaded to cache) | `R/onLoad.R` (`r5_jar_version`, `r5_jar_size`) **and** `inst/extdata/metadata_r5r.csv` | Bump both together; the cache dir `r5r/r5_jar_v<version>` is derived from the version and old caches are purged on load |
| Little JAR (shipped) | `r-package/inst/jar/r5r.jar` | CI-built on every push to a non-protected branch when the Gradle output's sha256 changes. **After pushing a change to `java-r5rcore/`, `git pull` before pushing again** — the bot has committed to your branch |
| Local R5 override | `options(r5r.r5jar = "<path>")` | Use to test an unreleased R5 without touching the pins |
| JVM flags | `start_r5r_java()` | `-DLOG_PATH=<data_path>/r5r-log.log`, `-DR5_VER`, `-DR5R_VER` are read back in `R5RCore.java` |
| Gradle build | `java-r5rcore/build.gradle` | Resolves the R5 JAR by running `download_r5()` through R and `JRI.jar` from the installed rJava; reproducible jar settings |

Full rule (path-scoped): [`.claude/rules/java-r5rcore-conventions.md`](.claude/rules/java-r5rcore-conventions.md).

## Troubleshooting ladder

Most r5r failures are environmental. Work these in order and record which came back clean before reading package source:

1. **Java** — exactly 21 (`r5r_sitrep()`; `rJava::.jcall("java/lang/System", "S", "getProperty", "java.version")`), `JAVA_HOME` pointing at it.
2. **JVM memory** — `options(java.parameters = "-Xmx<N>G")` set **before** `library(r5r)`; an already-started JVM ignores later changes (restart R).
3. **R5 JAR cache** — version/size check in `start_r5r_java()`; inspect or clear with `r5r_cache()`, re-download with `download_r5()`.
4. **Network** — stale `network.dat` built by another R5/r5r version, or a cached `r5r_network` object; rebuild with `build_network(overwrite = TRUE)`.
5. **Input data** — OSM `.pbf` coverage, `get_gtfs_errors()`, departure time inside the GTFS service period (`check_transit_availability()`), points that fail to snap (`find_snap()`), points not in WGS 84.
6. **R → Java** — the argument's path through `assign_*()` / `set_*()` (`R/assign.R`, `R/set.R`) to `RoutingProperties.java`.
7. **Java / R5** — `java-r5rcore/src`, then upstream R5 behaviour.

For a GitHub issue, build the reprex on the `poa`/`spo` sample data in `r-package/inst/extdata/`.

## Package Functions

Inputs contract: OSM street network `.pbf` (mandatory); one or more GTFS `.zip` feeds (optional); DEM raster `.tif` (optional). All routing functions take an `r5r_network` (S4, slot `jcore` = `org.ipea.r5r.R5RCore`).

| Function | File | Purpose |
| --- | --- | --- |
| `build_network()` | `R/build_network.R` | Downloads/caches the R5 JAR once, builds the multimodal network from `data_path`; writes `network.dat` and `gtfs_errors.csv` there. `setup_r5()` is its deprecated alias |
| `accessibility()` | `R/accessibility.R` | Access to opportunities per origin, mode and decay function (step, logistic, exponential, linear) → `data.table` |
| `travel_time_matrix()` | `R/travel_time_matrix.R` | Fast OD travel times for a departure time → `data.table` |
| `arrival_travel_time_matrix()` | `R/arrival_travel_time_matrix.R` | OD travel times constrained by arrival time, with routes and time breakdown |
| `expanded_travel_time_matrix()` | `R/expanded_travel_time_matrix.R` | OD travel times with routes and access/wait/in-vehicle/transfer breakdown |
| `detailed_itineraries()` | `R/detailed_itineraries.R` | Alternative routes per OD pair as `sf` LINESTRING segments with mode, time, distance |
| `pareto_frontier()` | `R/pareto_frontier.R` | Travel time × monetary cost frontier per OD pair → `data.table` |
| `isochrone()` | `R/isochrone.R` (+ `travel_time_surface.R`, `surface_isochrone.R`, `webmercator.R`) | Reachable area polygons per origin and cutoff → `sf` (Web Mercator travel-time surface + marching squares since 2.4.0) |

Support functions: `download_r5()`, `r5r_cache()`, `r5r_sitrep()`, `stop_r5()`, `find_snap()`, `street_network_to_sf()`, `transit_network_to_sf()`, `street_network_bbox()`, `get_gtfs_errors()`, `check_transit_availability()`, `setup_fare_structure()` / `read_fare_structure()` / `write_fare_structure()`. Internals: `set.R` (`set_*()` push routing parameters into Java `RoutingProperties`), `assign.R` (input validation/coercion), `java_utils.R` (`java_to_dt()` converts the Java `RDataFrame` back to `data.table`).

Sample data in `inst/extdata/`: `poa/` (Porto Alegre: OSM, two GTFS feeds, elevation, hexgrid, POIs, congestion and LTS scenarios, fares) and `spo/` (São Paulo: OSM, GTFS, hexgrid). Tests build both networks.
